## Big Data Architecture
Big data architecture is the blueprint for managing, processing, and analyzing large-scale data within an organization. It addresses the 3 Vs of big data and ensures that data systems are scalable, reliable, and efficient. 
### Key Components 
- Data sources. 
- Data ingestion. 
- Data storage. 
- Data processing. 
- Data visualization. 
- Governance and security. 
I also learned about containerization, which enables applications and their dependencies to be packaged into isolated, reproducible environments. Docker is the tool commonly used for containerization. As a practical exercise, I used draw.io to design my first data architecture for an arbitrary global logistics company, from ingestion to transformation, and then connected it to Power BI/Tableau dashboards for visualization and Databricks for machine learning.

## Data Security
Data security focuses on preventing unauthorized access and data breaches. This is achieved through the CIA triad: confidentiality, integrity, and availability. 
### What I learned 
- Defense-in-depth as a layered security approach. 
- Security techniques such as encryption, erasure, masking, and resilience. 
- Data privacy regulations and standards such as GDPR, POPIA, ISO/IEC 27001, and ISO/IEC 27701.

## Data Quality
Data quality refers to the set of measures used to ensure that data meets the needs of users and the purpose for which it was created. 
### Best Practices 
- Quality management. 
- Governance. 
- Security and privacy. 
- Integration. 
- Visualization. 
- Analysis.

## Data Lineage
Data lineage helps users understand data by showing where it came from, how it was transformed, and its current state. 
### Concepts Introduced 
- **Catalog**: An inventory of all data assets within an organization or division.
 - **Dictionary**: Metadata describing a dataset in one or more formats. 
- **Features**: A deeper concept with five components: 
- Transform.
 - Store.
- Serve.
- Monitor. 
- Registry.
I also learned about business users and technical users, and how their lineage needs can be served through the same pipeline, with one view being high-level and the other more detailed.
